# Research Archive Builder

논문 PDF 묶음에서 시작해 **연구 도록** 사이트를 만드는 하네스다. 첫 실전(정인용, 논문 23편 해설, 2026-10)에서 사용자 피드백을 거쳐 굳힌 방법이다. 산출물 예시는 이 저장소 자체(`index.html`, `posts/`, `assets/`)다.

작업을 시작하기 전에 반드시 읽을 것:
1. `references/lessons.md`: 사용자가 실제로 고쳐 달라고 한 것들. 같은 실수를 반복하지 않기 위한 규칙.
2. `references/plan-large-corpus.md`: 논문이 많고 연구 철학을 직접 추론해야 할 때의 단계별 계획.
3. 해당 단계의 프롬프트 템플릿: `references/agent-prompts.md`.

## 산출물 구조

```
index.html                홈: 머리말(핵심 질문) → 이런 상황이라면? → 연구 도록(질문별/주제별 색인 + 상세) → 소개 → 논문 전체 → 기록 → 연락
posts/<slug>.html         대표 논문 해설(인터랙티브)
assets/catalog.js         모든 데이터(QUESTIONS, TOPICS, POSTS, P, ...). window.CATALOG로 노출
assets/site.js            글 공통 부품: 상황 카드, 결론 블록, 연결 섹션, 눈금 말풍선
assets/site.css           디자인 시스템(토큰, 컴포넌트). 글꼴도 여기서 불러옴
DESIGN.md                 디자인 계약서. 새 페이지 전에 먼저 읽기
```
`template/`에 이 구조의 판이 있다(본보기 글 1편과 최소 catalog 포함, 회귀 검사 통과). 새 저장소라면 복사해서 시작하되, `index.html`의 머리말, 소개, 연락, 사진(`assets/profile.png`, 템플릿에는 없음)은 정인용 사이트의 것이므로 새 주인에 맞게 바꾸거나 뺀다. 논문 위주 사이트라면 소개와 기록 섹션은 줄이고 '한눈에 보기'(연도 × 주제)와 검색을 키운다.

## 단계 (요약. 자세한 것은 plan-large-corpus.md)

0. **분류(Triage)**: PDF마다 첫 쪽만 `pdftotext -l 1`로 읽어 제목, 학술지, 연도, 저자 순서를 표로 만든다. `cmp`로 중복 파일을 찾는다. 프리프린트, 종설, 학회 초록을 구분한다.
1. **논문 카드**: 모든 논문을 끝까지 읽고 `references/data-schema.md`의 카드(JSON)를 만든다. 에이전트에게 나눠 맡긴다. 카드에는 쪽 번호를 단 근거 인용을 넣는다.
2. **연구 철학 추론**: 카드만 모아 반복되는 질문, 방법, 대상, 태도를 찾는다. 모든 주장에 근거 논문 2편 이상을 붙인다. 초안을 사용자에게 보여 주고 확인받는다(가장 중요한 체크포인트).
3. **등급 나누기**: 모든 논문은 카드(목록과 도록 색인)로, 대표 논문만 해설 글로. 기준은 plan 문서.
4. **디자인**: `DESIGN.md`가 있으면 그것이 계약이다. 새 사이트라면 주제에서 방향을 끌어내고 design-pick으로 팩 2~3개를 사용자에게 고르게 한다. avoid-ai-design, antislop-ui 규칙을 지킨다.
5. **해설 글 작성**: 에이전트 1명 = 논문 1편. 프롬프트 템플릿을 그대로 쓴다.
6. **통합**: 에이전트 보고서를 받아 catalog.js에 항목을 추가하고, 결론 문장은 논문의 Conclusion 절을 직접 읽고 쓴다.
7. **검수**: `references/qa.md`의 순서. 스크립트 `scripts/qa_all.mjs`, `scripts/voice_check.py`.
8. **완성된 것부터 커밋**: 에이전트가 쓰는 중인 파일은 커밋하지 않는다.

## 절대 규칙 (어기면 사용자가 바로 지적했다)

- 저자 자신의 논문을 비판하지 않는다. 오류, 오타, 표와 본문 불일치는 페이지에 쓰지 않고 표 값으로 조용히 맞춘 뒤 사용자에게만 보고한다. 한계는 논문이 스스로 밝힌 것만.
- 과장하지 않는다. 논문이 검증하지 않은 효과는 '다음 질문'으로만 쓴다.
- 숫자는 논문에서만. 그림에서 읽은 값은 "그림에서 읽은 대략값", 직접 계산한 값은 "계산값", 만든 예시는 "가상 예시"로 표시. 논문에 없는 비교 기준(우연 수준, 다수 클래스 정확도 등)을 덧붙이지 않는다.
- 저자 역할은 사용자가 준 분류와 논문의 동등 기여 표기를 모두 대조한다. 다르면 사용자 분류를 따르고 물어본다.
- 프리프린트는 기본적으로 뺀다. 넣으라고 하면 해설 글에만 경고 상자를 두고 홈 색인과 목록에는 조용히.
- 독자에게 개발용 문구, 브라우저에만 저장되는 투표나 반응, 연결 안 된 댓글 자리를 보여 주지 않는다.
- 이모지 아이콘, 링크 끝 화살표, 'A · B · C' 메타, 대문자 라벨, 모든 면의 둥근 모서리와 그림자, 왼쪽 색 띠 상자를 쓰지 않는다.
